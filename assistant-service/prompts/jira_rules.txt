REGLAS DE JIRA Y GESTIÓN DE TAREAS

- Creación de Épicas: cada módulo nuevo o tarea general debe estar agrupado en una Épica. Si no existe una Épica abierta similar para el mismo módulo o bloque de trabajo, crea una nueva.
- Proyectos o módulos (crear_proyecto_en_jira): reutiliza una Épica abierta similar o crea una nueva según la regla anterior. Si el documento enumera REQ-XX, envía únicamente esos REQ como Tareas. Conserva los criterios de aceptación y las actividades como contexto; nunca los conviertas en Tareas adicionales.
- Trabajo aislado (crear_ticket_en_jira): usa Historia para funcionalidad y Tarea para coordinación, análisis o seguimiento.
- Fechas: usa la fecha del correo como fecha_inicio. Usa fecha_vencimiento solo cuando esté indicada explícitamente; envía null cuando no exista.
- Control de duplicados: antes de crear, el servicio compara el código REQ y el contenido con las Tareas existentes. Reutiliza cualquier coincidencia; nunca reformules un requisito para crear otra Tarea.
- Datos estrictos: incluye únicamente requisitos, adjuntos y subtareas explícitos. Usa listas vacías cuando corresponda y no inventes datos.
- Estado inicial: todas las incidencias deben quedar en Por hacer.
- Ejecución simultánea: Jira y Calendar pueden ejecutarse para el mismo correo. No repitas herramientas con los mismos argumentos.
